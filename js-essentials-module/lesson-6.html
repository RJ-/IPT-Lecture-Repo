6.1 What is Node.js?

Node.js is a program that runs JavaScript outside the browser. It takes the JavaScript engine from Google Chrome (called V8) and adds the things a server needs: access to files, the network, and the operating system. It was released in 2009, and it is why JavaScript is now a back-end language too.

Why can't the browser just connect to the database directly? It would be simpler.

Because anything in the browser can be read and changed by the user. If the browser held the database password, anyone could open the developer tools, copy it, and delete or steal every record. The server is the trusted middleman: it keeps the secrets, checks every request, and only does what the rules allow.

Express is the most popular framework for building web servers in Node.js. Here is a complete server. Read the line notes, then press Run.

  • line 2 Create the application object — your server.

Everyday analogy

A server is like the registrar's office. Each window is a route: "Window 1 — enrollment" (POST /api/enroll), "Window 2 — request TOR" (GET /api/records/:id). A student (the client) goes to a window with a request form; the clerk (your route function) checks it and hands back a response. If you go to a window that does not exist, you are told "not here" (404).

6.4 REST: a shared way to design APIs

REST is a set of conventions that make APIs predictable. Think in resources (nouns, like students) and use the HTTP method as the verb:

Method + pathActionSuccess codeDatabase word (CRUD)
GET /api/studentslist all students200Read
GET /api/students/7get student 7200 (or 404)Read
POST /api/studentscreate a new student (data in the body)201Create
PUT /api/students/7update student 7200Update
DELETE /api/students/7remove student 7204Delete
Which is the better REST design: GET /api/deleteStudent?id=7 or DELETE /api/students/7? Why?

DELETE /api/students/7. The URL names the resource, and the method states the action. Using GET for a delete is also dangerous: browsers, search engines and link previews freely repeat GET requests, assuming they are safe — and could delete data by accident.

6.5 Route parameters and query strings

Two ways a client sends small pieces of information in the URL:

  • Route parameter — part of the path, for which resource: /api/students/7 → req.params.id
  • Query string — after ?, for filtering or options: /api/students?section=2A → req.query.section
  • line 18 :id in the path is a placeholder. Whatever is in that spot of the URL appears in req.params.id.
  • line 19 Everything in a URL arrives as a string. "2" === 2 is false (Lesson 1!), so convert with Number().
  • line 22 Send the right status code. return stops the function so we do not try to send a second response.

6.6 Receiving data: POST and express.json()

When a client POSTs JSON (like you did in Lesson 5), the data arrives in the request body. Express does not read bodies by default — you must add app.use(express.json()). Then the parsed object is in req.body.

The server must also validate the data. Never trust what a client sends: it may be missing fields, have the wrong type, or be deliberately harmful.

6.8 Middleware: code that runs between request and route

Middleware is a function that sees every request before it reaches a route. It can log, check a login token, parse the body, or reject the request. It receives a third argument, next; calling next() passes the request along the line. express.json() is middleware, and so is cors(), which you will meet in Lesson 7. Summary

  • Node.js runs JavaScript on the server, with access to files, networks and databases.
  • npm installs packages; package.json lists them.
  • Express: app.get/post/put/delete(path, (req, res) => …), then app.listen(port).
  • REST: nouns in the URL, verbs as methods, honest status codes (200, 201, 204, 400, 404).
  • req.params (path), req.query (after ?), req.body (needs express.json()).
  • Always validate input on the server. Middleware runs before routes and calls next().

What is Node.js?

  • A new programming language based on Java.
  • A runtime that lets JavaScript run outside the browser, for example on a server.
  • A database for JavaScript.
  • A front-end library like React.

Node.js uses Chrome's V8 engine plus server features (files, network) to run JavaScript anywhere.

Which REST endpoint best fits "create a new student"?

  • GET /api/createStudent
  • PUT /api/students/new
  • POST /api/students
  • DELETE /api/students

POST to the collection creates a new item. The URL names the resource; the method is the action.

For the route app.get("/api/students/:id", …) and the request /api/students/15, what is req.params.id?

  • "15" (a string)
  • 15 (a number)
  • ":id"
  • undefined

Route parameters always arrive as strings. Convert with Number() before comparing to numeric ids.

A POST route always finds req.body is undefined. What is the most likely cause?

  • The route should be GET.
  • The port is wrong.
  • res.json() was not called.
  • app.use(express.json()) was not added.

Express only parses JSON bodies when the express.json() middleware is in place.

A client sends a new task with no title. Which response is most appropriate?

  • 200 OK
  • 400 Bad Request with an error message
  • 500 Internal Server Error
  • 201 Created

The client sent invalid data, so it is a client error: 400. A 500 means the server itself failed.

In Express middleware, what does calling next() do?

  • Ends the request with status 200.
  • Restarts the server.
  • Passes the request on to the next middleware or route.
  • Sends the request to the next server.

Middleware either responds (and stops the chain) or calls next() to let the request continue.
