8.1 Real-time communication: WebSockets · Week 7

HTTP is request–response: the client always asks first. But a chat app, a live scoreboard or a delivery tracker needs the server to push updates the moment they happen. A WebSocket opens one connection that stays open, so either side can send a message at any time.

ProtocolShapeTypical use
HTTP (REST)client asks → server answers, then doneloading pages, CRUD APIs
WebSocketone open, two-way connectionchat, live dashboards, multiplayer games
gRPCfast binary calls between services, using a strict schemamicroservice-to-microservice traffic

Patterns you know: event listeners with callbacks ("connection", "message"), JSON in both directions, and DOM updates. Many projects use the Socket.IO library, which adds rooms and automatic reconnection on top of this idea.

8.2 Databases: SQL and NoSQL · Week 8

In Lessons 6–7, data lived in an array and vanished on restart. In a real system, routes read and write a database. Node.js has drivers for every major database. Notice that the route looks the same — only the line that touches the data changes, and it now uses await, because a database is slow, just like the network.

Security: SQL injection

Never build SQL by joining strings: "… WHERE id = " + req.params.id. A visitor could send 1 OR 1=1 — or worse — and change your query. Always use placeholders (?) and pass values separately, as above. The driver then treats the input strictly as data.

A system keeps orders in MySQL but caches product details in MongoDB. A product's price changes in MySQL. What problem could appear, and what is it called?

The two stores can disagree — customers might see the old price from MongoDB. Keeping them consistent is data synchronization. Common strategies: update both in the same route, send an event (e.g., through a message queue) that the other side listens for, or give cached data a short expiry time.

8.3 Microservices: services calling services · Weeks 6 & 16

A microservices architecture splits one big back end into small services, each owning one job and its own data. They talk to each other over HTTP — using exactly the fetch you learned in Lesson 5, but now from one server to another. Run this: two services on two ports.

It should degrade gracefully instead of crashing. Line 24 falls back to "(unknown)" if the Users service does not answer OK. In a large system, each service must expect others to fail sometimes — adding timeouts, retries and fallbacks is a big part of microservice design.

8.4 Cross-platform mobile apps: React Native · Weeks 4, 5 & 15

React Native lets you build real Android and iOS apps in JavaScript. Instead of HTML tags it uses native components like <View>, <Text> and <FlatList> — but the logic, the fetch calls and the API are exactly the same as your web front end. One back end can serve the website and the mobile app.

Compare it with the React web component in Lesson 7.5: almost line for line the same. (Flutter, the other tool in the outline, uses the Dart language instead — but it calls the same REST API with the same JSON.)

8.5 Serverless functions: AWS Lambda · Weeks 10 & 17

With serverless computing you do not run a server at all. You upload a single function; the cloud provider runs it only when a request arrives, scales it automatically, and charges per use. On AWS Lambda a Node.js function is just an exported async function that receives an event object and returns a response object.

Patterns you know: an async function, an object in, an object out, and JSON.stringify for the body. It is an Express route without the server. (?. is "optional chaining": if queryStringParameters is missing, it gives undefined instead of crashing.)

8.6 WebAssembly: JavaScript working with other languages · Week 3

WebAssembly (Wasm) is a compact binary format that browsers can run at near-native speed. Code written in C, C++ or Rust can be compiled to .wasm, then JavaScript loads it and calls its functions. JavaScript stays in charge of the page; Wasm does the heavy number-crunching (image editing, games, video, scientific code).

Normally you would compile a C++ function like int add(int a, int b) { return a + b; } with a tool such as Emscripten. Below, the compiled bytes are written out by hand so you can run it right here.

The integration idea: two languages, one program. JavaScript loads the module (asynchronously, with await) and calls its exports like normal functions. This is the browser counterpart of the Python + C++ (Cython) technique from Week 3.

8.8 Automated tests and CI/CD · Week 13

When many parts are integrated, a small change in one can break another. Automated tests check that each part still works. Continuous Integration (CI) runs those tests automatically on every push to GitHub, and Continuous Deployment (CD) publishes the new version only if they pass.

Summary

  • WebSockets keep a two-way connection open for real-time features.
  • Routes read and write databases with await; always use query placeholders.
  • Microservices call each other with fetch and must handle each other's failures.
  • React Native reuses your JavaScript skills and the same API for mobile apps.
  • A Lambda function is an async function that turns an event object into a response object.
  • WebAssembly lets JavaScript call fast code compiled from other languages.
  • Modularize, keep secrets in environment variables, validate everything, and let CI run your tests.

A live basketball scoreboard must update on every viewer's screen the instant a basket is scored. Which technology fits best?

  • A REST GET request every 10 minutes
  • A PDF report
  • WebSockets
  • A static HTML page

WebSockets keep a connection open so the server can push updates immediately.

Which database query is safe from SQL injection?

  • db.query("SELECT * FROM students WHERE id = ?", [id])
  • db.query("SELECT * FROM students WHERE id = " + id)
  • db.query(`SELECT * FROM students WHERE id = ${id}`)
  • All are equally safe.

Placeholders send the value separately so it is treated as data, never as SQL. Template literals and + both build the query from raw input.

In a microservices system, how does the Orders service get a customer's name from the Users service?

  • By reading the Users service's variables directly.
  • By sharing one global array.
  • By copying the Users code into Orders.
  • By sending an HTTP request (e.g., with fetch) to the Users service's API.

Each microservice owns its data and exposes it only through its API.

What does an AWS Lambda function written in Node.js look like?

  • A full Express server with app.listen().
  • An exported async function that receives an event object and returns a response object.
  • A Java class with a main method.
  • An HTML page.

Serverless platforms call your handler with an event; you return { statusCode, body }.

Where should a database password for your Node.js API be kept?

  • In server.js, so it is easy to find.
  • In the front-end JavaScript.
  • In an environment variable (e.g., a .env file listed in .gitignore).
  • In the README on GitHub.

Secrets must never be committed to a repository or sent to the browser.

What does a CI pipeline like the GitHub Actions example do?

  • Automatically installs dependencies and runs the tests on every push, reporting pass or fail.
  • Writes the tests for you.
  • Replaces the need for a server.
  • Converts JavaScript into Java.

Continuous Integration automates build-and-test so broken changes are caught immediately.
