1.1 Why JavaScript, and why in IPT1?

JavaScript was created in 1995 by Brendan Eich at Netscape — famously in about ten days — to make web pages interactive. For years it lived only inside the browser. Today it runs almost everywhere:

Browserevery web page you open
ServerNode.js APIs and microservices
MobileReact Native apps
Cloudserverless functions (AWS Lambda)
DesktopVS Code, Discord, Slack (Electron)

That is exactly why it matters in Integrative Programming. Integration is about making different parts of a system talk to each other. When the front end, the back end, the mobile app and the cloud function are all written in JavaScript, a team can share code, share data formats, and move between layers without learning a new language each time.

Not the same as Java

JavaScript and Java share four letters and some curly-brace syntax, and that is about all. The name was a marketing decision in 1995, when Java was popular. The official standard for the language is called ECMAScript — you will see names like "ES6" or "ES2015" for the modern version we use in this module.

1.2 Your first line: console.log()

In C++ you print with cout; in Java with System.out.println(). In JavaScript you use console.log(). Press ▶ Run below.

  • line 1 // starts a one-line comment — same as C++ and Java.
  • line 2 Text inside quotes is a string. You may use double quotes "…" or single quotes '…'.
  • line 3 Commas let you print several values on one line. JavaScript computes 1 + 2 first.
  • line 5–6 /* … */ is a multi-line comment.

Notice what is missing compared with Java: no class, no public static void main, no compiling. JavaScript runs top to bottom, line by line. Semicolons at the end of lines are optional in most cases, but we will always write them — it is a good habit and avoids rare bugs.

1.3 Variables: let and const

A variable is a labelled box that holds a value. In Java you must say what type goes in the box: int age = 19;. In JavaScript you only say whether the box can be changed later:

KeywordMeaningUse it when…
constThe label can never point to a new value.Default choice. Most values never need to change.
letThe value can be reassigned.Counters, totals, anything that changes.
varThe old (pre-2015) way.Avoid it. You will see it in old code online — read it as "let, with surprises".
Why should const be your default, if let can do everything const can?

Because const is a promise to the reader (and to your future self): "this value will not change." When you see let, you know to watch for a change somewhere below. Fewer moving parts means fewer bugs. If you uncomment the last line above, you get TypeError: Assignment to constant variable — JavaScript protects the promise for you.

Naming rules are similar to Java: start with a letter, _ or $; no spaces; case-sensitive (total and Total are different). The JavaScript convention is camelCase: studentName, finalGrade, isEnrolled.

1.4 Data types

JavaScript is dynamically typed: the value has a type, but the variable does not. The same let box can hold a number now and a string later. (Java would refuse to compile that.)

This freedom is convenient, but it also means some mistakes only show up when the code runs. That is one reason many teams add TypeScript (JavaScript plus type annotations) on large projects.

1.5 Operators

Arithmetic works like you expect: + - * /, plus % (remainder) and ** (power). There is no separate integer division: 7 / 2 is 3.5, not 3.

The + trap: numbers vs strings

When + sees a string on either side, it joins instead of adds. This matters a lot when data comes from a form or a web request, because that data usually arrives as text.

Comparison: always use ===

JavaScript has two equality operators. == ("loose") converts types before comparing, which produces strange results. === ("strict") checks that both the value and the type match. Use === and !== every time.

Logical operators

Same as Java and C++: && (and), || (or), ! (not).

A form sends "20" (a string) for quantity. Your code does quantity + 1 and saves the result. What gets saved, and how do you fix it?

It saves "201" — the string "20" joined with 1. Fix it by converting first: Number(quantity) + 1 gives 21. This exact bug is common when a front end sends data to a back end, which is why both sides should check and convert their inputs.

1.6 Strings and template literals

Joining strings with + gets messy fast. Modern JavaScript has template literals: use backticks `…` (the key above Tab) and put any expression inside ${ }.

Summary

  • JavaScript runs in browsers, servers, phones and the cloud — one language across every layer of an integrated system.
  • console.log() prints. // and /* */ are comments.
  • Use const by default and let when a value must change. Avoid var.
  • Values have types (number, string, boolean, undefined, null, object); variables do not. Check with typeof.
  • + joins when a string is involved — convert with Number(). Compare with ===.
  • Template literals: `Hello ${name}`.

Why is JavaScript especially useful for integrative programming?

  • It is the fastest programming language.
  • It is the same language as Java.
  • It can run on the browser, server, mobile and cloud, so one language can cover several layers of a system.
  • It does not need a computer to run.

JavaScript's reach — browser, Node.js servers, React Native, serverless — lets one team and one data format span the whole system.

Which declaration is the best default for a value that will never change?

  • var
  • const
  • let
  • int

const signals that the value will not be reassigned. int is not a JavaScript keyword.

What does console.log("4" + 4) print?

  • 8
  • "8"
  • an error
  • 44

When either side of + is a string, JavaScript joins them as text: "44".

What is the result of 10 === "10"?

  • false
  • true
  • undefined
  • an error

Strict equality checks the type too. A number is not a string, so the result is false.

Given let x = 5; x = "five";, what happens in JavaScript?

  • Compile error, like Java.
  • The program crashes when it runs.
  • It works; x now holds a string.
  • x becomes undefined.

JavaScript is dynamically typed. A let variable can hold a value of any type.

Which line correctly prints Score: 18 using a template literal (with score = 18)?

  • console.log("Score: ${score}")
  • console.log(`Score: ${score}`)
  • console.log('Score: {score}')
  • console.log(`Score: $score`)

Template literals need backticks and the ${ } placeholder. With ordinary quotes, ${score} is printed literally.
