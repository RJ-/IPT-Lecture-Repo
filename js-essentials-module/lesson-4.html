4.2 The DOM: how JavaScript sees your page

When the browser reads your HTML, it builds a tree of objects in memory called the DOM (Document Object Model). Every tag becomes an object (a "node") that JavaScript can find and change. When JavaScript changes a node, the browser immediately redraws that part of the page.

Your HTMLThe DOM tree the browser builds

The whole tree is available to your script through a built-in object called document.

Almost all DOM code follows two steps: find the element, then change it.

  • line 11 textContent replaces the text inside the element.
  • line 14 .note means "the first element with class note".
  • line 17 querySelectorAll returns a list of all matches, which has forEach.
textContent vs innerHTML

el.innerHTML = "<b>Hi</b>" treats the text as HTML and builds tags from it. That is useful, but never put text typed by a user into innerHTML: a user could type a <script> or <img onerror=…> and run code on other people's screens. This attack is called XSS (cross-site scripting). For user text, use textContent.

4.5 Events: reacting to the user

An event is something that happens on the page: a click, a key press, a form being submitted. You tell an element "when this event happens, run this function" with addEventListener. Yes — that function is a callback, just like in Lessons 2 and 3.

  • line 7 The data lives in a JavaScript variable.
  • line 10 "When #add is clicked, run this arrow function." The function does not run now — it runs later, every time someone clicks.
  • line 12 After changing the data, we update the page so it shows the new value. Change data → update the view. Remember this pattern; it is the core idea behind React.

If you reload this page, the guest list is empty again. Why? And where should the list be stored so everyone sees the same guests?

The list exists only in this browser's memory (the DOM). Reloading throws it away, and other people's browsers never had it. To keep and share data, the page must send it to a server, which stores it in a database. That is exactly the front end ↔ back end integration you will build in Lessons 6 and 7.

Summary

  • The browser turns HTML into the DOM, a tree of objects JavaScript can change.
  • document.querySelector(selector) finds; textContent, style, classList change.
  • el.addEventListener("click", callback) runs code when the user acts.
  • In forms, call event.preventDefault() and read input.value.
  • createElement → set content → appendChild adds new elements.
  • Use textContent for user input to avoid XSS.
  • Change the data, then re-render the view — the idea behind front-end frameworks.

What is the DOM?

  • A database that stores web pages.
  • A CSS framework.
  • The tree of objects the browser builds from HTML, which JavaScript can read and change.
  • The server that sends HTML.

The Document Object Model is the browser's in-memory representation of the page.

Which line selects the element <p id="status">?

  • document.querySelector("#status")
  • document.querySelector(".status")
  • document.querySelector("status")
  • document.get("status")

# selects by id, . by class, and a bare word by tag name — same as CSS.

Why do we call event.preventDefault() in a form's submit handler?

  • To delete the form.
  • To validate the input automatically.
  • To send the data to the server.
  • To stop the browser from reloading the page, so JavaScript can handle the data.

The default action of submitting a form is to navigate/reload. Preventing it keeps the page and your JavaScript state.

A user types a comment that will be shown on the page. Which is the safe way to display it?

  • el.innerHTML = comment
  • el.textContent = comment
  • document.write(comment)
  • eval(comment)

textContent shows the text as text. The others can run code the user typed (XSS).

In btn.addEventListener("click", showMenu), when does showMenu run?

  • Immediately, once.
  • When the page loads.
  • Each time the button is clicked.
  • Never, unless you call it again.

showMenu is a callback. The browser calls it every time the click event happens.

Which pattern describes how front-end frameworks like React work?

  • Keep the data in JavaScript; when it changes, re-render the view from the data.
  • Write all HTML by hand and never change it.
  • Store all data in CSS classes.
  • Reload the whole page after every click.

"State changes → view updates" is the core idea behind React, Vue and Angular.
